# 📋 Document 01 — Project Requirement Document (PRD)

## **Shavisha Thiloshini — Personal Portfolio Website**

**Document Version:** 1.0
**Project Type:** Personal Developer Portfolio
**Primary Purpose:** CV / Recruiter Portfolio
**Status:** Planning
**Owner:** Shavisha Thiloshini

---

## 1. Project Overview

The **Shavisha Thiloshini Personal Portfolio** is a modern, interactive personal website designed to professionally present Shavisha's skills, education, experience, projects, achievements, and contact information.

The website will function as an extension of her CV, giving recruiters, potential employers, collaborators, and other visitors a more engaging way to understand her technical abilities, design interests, projects, and professional development.

The portfolio will combine:

* 💻 Frontend development
* 🎨 UI/UX design
* 🌌 3D visual experiences
* ✨ Smooth animations
* 📱 Responsive design
* 📄 CV accessibility
* 🚀 Project case studies

The overall experience should feel **professional, elegant, futuristic, personal, and highly polished** without becoming visually overwhelming.

---

# 2. Project Vision

### Vision Statement

> **Create a memorable personal digital experience that demonstrates Shavisha's ability to combine software development, UI/UX design, creativity, and communication.**

The portfolio should not simply list qualifications.

It should **demonstrate them through the website itself**.

A recruiter should be able to understand within a short visit:

> **Who Shavisha is → What she can do → What she has built → How she thinks → How to contact her.**

---

# 3. Project Objectives

### Primary Objectives

1. Create a professional online identity for Shavisha.
2. Showcase selected software projects.
3. Present technical and UI/UX skills clearly.
4. Provide easy access to the CV/resume.
5. Highlight education and professional experiences.
6. Demonstrate frontend development ability through the portfolio itself.
7. Demonstrate UI/UX design ability through the visual system.
8. Create a memorable experience using tasteful 3D and animation.
9. Provide recruiters with clear contact and social links.
10. Establish a portfolio suitable for linking from the CV and professional profiles.

# 25. Backend Requirement

A traditional backend/database is **not automatically required**.

The project should remain primarily frontend-focused unless a real requirement emerges.

Possible requirements include:

### Option A — No Backend

Static portfolio + external contact service.

### Option B — Lightweight Serverless Contact

Use a serverless/API-based service for contact submissions.

### Option C — Backend

Only introduce a dedicated backend/database if the project requirements justify it.

The final technical decision will be documented in the **TRD** and **Backend Schema Document**.

---

Initially, portfolio content may be maintained through structured frontend data.

```text
education/

```

# 27. Security Requirements

The portfolio should:

* Avoid exposing secret API keys
* Validate contact inputs
* Protect any serverless/API endpoints
* Avoid storing unnecessary personal information
* Prevent spam where contact functionality requires it

* 3D enhances the experience.

### Technical

* Fully responsive
* Good performance
* Accessible
* SEO-ready
