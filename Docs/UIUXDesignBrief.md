# Document 04 — UI/UX Design Brief

### Shavisha Thiloshini Personal Portfolio Website

**Version:** 1.0
**Status:** Design Direction
**Purpose:** Define the complete visual and interaction system before frontend implementation.

---

## 1. Design Vision

The portfolio should **not feel like a standard developer portfolio template**.

It should feel like a personal digital space that communicates:

> **“I’m a software engineering student who builds things, cares about design, keeps learning, and has more than just technical skills.”**

The visual direction combines:

* 🌑 Dark creative-tech aesthetic
* ✨ Minimal futuristic details
* 🧊 Subtle glass/depth effects
* 🌀 Tasteful 3D interaction
* 🎞️ Smooth motion
* 📐 Strong structure and alignment
* 💼 Professional recruiter-friendly presentation
* 🎨 Personal visual identity

The design should balance **creativity and professionalism**.

The 3D elements should create the WOW factor, but the portfolio content must remain the main character.

---

# 2. Core Design Principles

### 2.1 Minimal but Not Empty

Use generous whitespace and strong typography rather than filling every area with decorative elements.

### 2.2 Structured, Not Chaotic

Every major element should have a clear visual relationship with surrounding content.

**Important:** Skills must remain structured and aligned. No floating skill bubbles, scattered skill planets, or random skill positions.

### 2.3 Motion With Purpose

Animations should communicate:

* hierarchy
* interaction
* progression
* depth
* transitions

Not simply exist because animation is possible.

### 2.4 3D With Restraint

3D is primarily a **hero experience** and supporting visual layer.

It should not turn the entire website into a game.

### 2.5 Recruiter First

A recruiter should be able to understand:

**Who she is → What she builds → What she knows → What she has done → How to contact her**

within a short visit.

# 4. Color System

The primary interface will use a **dark-first palette**.

### Primary Background

`#080A0F`

Very dark blue-black.

### Secondary Background

`#0E1118`

Used for alternate sections and elevated areas.

### Surface

`#151923`

Used for cards and content containers.

### Elevated Surface

`#1B202C`

Used for hover states and higher-level cards.

### Primary Text

`#F4F6F8`

High-contrast main typography.

### Secondary Text

`#A6ACB8`

Supporting descriptions and metadata.

### Muted Text

`#6F7684`

Low-priority information.

### Accent

A sophisticated **teal/cyan accent** will connect the portfolio with the user's previous visual preferences while keeping the portfolio professional.

Suggested:

`#4FD1C5`

### Accent Highlight

`#7DE7DE`

Used sparingly for hover states and important highlights.

### Gradient

Gradients should be subtle.

Example concept:

`Teal → Blue → Transparent`

Gradients should primarily appear in:

* 3D lighting
* background atmosphere
* selected text highlights
* buttons
* hover states

—not across every section.

# 5. Typography

Because this is a personal portfolio, typography should become part of the identity.

### Heading Font

**Bricolage Grotesque**

Usage:

* Hero name
* Section headings
* Project titles
* Large statements

It provides a distinctive editorial/creative feel without becoming difficult to read.

### Body Font

**Instrument Sans**

Usage:

* Paragraphs
* Navigation
* Buttons
* Metadata
* Project descriptions
* Forms

This creates a clean contrast between personality and readability.

### Typography Hierarchy

| Element         | Style              |
| --------------- | ------------------ |
| Hero Name       | Extra large / bold |
| Hero Subtitle   | Medium / clean     |
| Section Heading | Large / bold       |
| Project Heading | Large              |
| Card Heading    | Medium             |
| Body            | Regular            |
| Metadata        | Small              |
| Labels          | Small / uppercase  |

Typography should use **large scale differences** rather than excessive decoration to establish hierarchy.

The hero should contain **one main 3D visual concept**.

A stylized floating **3D digital workspace / abstract architectural object** containing subtle elements representing:

* code
* design
* creativity
* learning

Alternative:

A polished abstract 3D geometric structure with:

* layered shapes
* subtle teal lighting
* depth
* glass-like surfaces
* soft atmospheric lighting

The object should feel like a **personal visual signature**.

## 9.1 3D Interaction

Mouse movement:

* subtle camera movement
* slight object rotation
* parallax

Scroll:

* camera shifts slightly
* object moves deeper into the scene
* hero transitions into the next section

* subtle lighting response

The movement should be damped and smooth.

**No aggressive spinning.**

# 27. Scroll Animation System

Animation should follow a consistent language.

### Section Entrance

* opacity: 0 → 1
* translateY: 20–30px → 0

### Project Images

* scale: 0.97 → 1
* opacity: 0 → 1

### Timeline

Items reveal progressively as they enter viewport.

### Text

Headings may use subtle word/line reveals.

### Hero

The strongest animation happens here.

---

# 28. Animation Timing

Suggested principles:

| Interaction      |            Duration |
| ---------------- | ------------------: |
| Hover            |           150–250ms |
| Button           |           150–250ms |
| Card             |           250–400ms |
| Section reveal   |           500–800ms |
| Hero 3D movement | Continuous / damped |
| Page transition  |           400–700ms |

Animations should use smooth easing rather than linear movement.

---

# 29. Cursor Interaction

Desktop may have a subtle custom cursor enhancement.

Normal:

Small cursor.

Interactive element:

Cursor slightly expands or changes state.

Avoid:

❌ Giant circle follower
❌ Excessive trails
❌ Magnetic effects everywhere

The cursor should remain almost invisible unless the user interacts with something.

# 30. Responsive Design

## Desktop

Full experience:

* 3D hero
* multi-column layouts
* project showcases
* timeline
* hover interactions

## Tablet

Reduce:

* 3D complexity
* particle count
* spacing
* typography scale

## Mobile

The portfolio should be intentionally redesigned rather than simply compressed.

Use:

* single-column content
* simplified 3D
* fewer particles
* smaller typography
* touch-friendly buttons
* horizontal overflow avoided
* comfortable spacing

---

1. Name
2. Role
3. Short description

---

# 32. Accessibility

The design must support:

* semantic HTML
* keyboard navigation
* visible focus states
* readable contrast
* meaningful alt text
* accessible buttons
* accessible form labels
* reduced-motion preference
* screen-reader-friendly navigation

### Reduced Motion

If the user has enabled reduced motion:

* disable major parallax
* reduce 3D movement
* remove unnecessary transitions
* preserve content and usability

---

# 33. 3D Fallback

If WebGL is unavailable:

Instead of showing a broken canvas:

Display a static visual composition.

Possible fallback:

* abstract gradient object
* optimized image
* SVG composition

The user should still receive a complete portfolio experience.

---

# 34. Performance UX

3D should never compromise usability.

Requirements:

* lazy-load heavy 3D assets
* optimize models
* limit particle count
* avoid unnecessary textures
* use compressed images
* animate only what needs animation
* reduce effects on mobile

The page should become usable quickly even if the 3D scene takes longer to initialize.
